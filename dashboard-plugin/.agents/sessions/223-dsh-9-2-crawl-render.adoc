== Constats d'ouverture

* `build.gradle.kts` (racine) : `configPath = "dashboard-plugin"` → le crawl ne
  lisait que l'`INDEX.adoc` du plugin (2 boroughs, 12 epics).
* `IndexCrawler.crawlDirectory` : `walkFileTree` **sans élagage** →
  `foundry/` pèse plus de 4 Go (`bakery-plugin`, `build/`, `.gradle/`,
  `node_modules/`) ; un `find` naïf dépasse 120 s.
* `parseIndex` était appelé **deux fois** par fichier (boroughs + epics).
* Aucune déduplication : les tables « Portefeuille » de chaque `INDEX.adoc`
  répètent les mêmes boroughs → doublons et propriétaires d'EPICs instables.
* `dashboard.thyme` : Bootstrap CSS/JS + vis.js chargés depuis
  `cdn.jsdelivr.net` / `unpkg.com` → rendu non offline, et canvas interactif
  interdit par la frontière DSH-BOUNDARY (décision 5).

== Travaux livrés

=== 1. Crawl complet et robuste (`IndexCrawler`)

* `crawlDirectory` élague `build`, `.gradle`, `.git`, `.kotlin`, `.idea`,
  `node_modules`, `out`, `target`, `dist`, `.venv`, `venv`, `.tox`,
  `__pycache__`, `.cache`, `backup`, `archives`.
* `visitFileFailed` tolérant (un fichier illisible ne casse pas le crawl).
* `parseIndex` appelé **une seule fois** par fichier.
* Déduplication par clé stable : borough = `project`, epic = `borough|id`,
  session = `borough|numéro` ; fusion « la ligne la plus riche gagne ».
* Propriétaire d'un EPIC/session résolu par le **chemin le plus profond**
  (normalisation des projets `workspace-agent (IntelliJ)` → `workspace-agent`).
* **Fallback de synthèse** : un borough qui se décrit sans table
  `Borough | Project` (attributs `:code-name:`, `_DAG_ : Nx`, prose) est
  synthétisé depuis le répertoire `foundry/public|private/<repo>/`. Exemples :
  `academy-gradle`, `bureau-gradle`, `conventions-gradle`,
  `container-provision-gradle`, `newpipe-gradle`, `notebook-gradle`,
  `office-template`, `video-kernel-gradle`.
* `cleanName` retire les marqueurs d'emoji des noms (`Newark 🔴` → `Newark`).

=== 2. Performance mesurée

[source]
----
Dashboard data written to …/dashboard-data.json
  (38 boroughs, 460 epics, 461 sessions) in 638ms
----

Le crawl de `foundry/` (38 projets, 4+ Go sur disque) s'exécute en **638 ms**
grâce à l'élagage. Sans élagage, le même parcours dépasse 120 s.

=== 3. Rendu

* **Couches DAG (N0 → N4)** : table statique groupée par niveau
  (borough + projet), niveaux inconnus affichés `N?` (fin des `()` vides).
  → *retrait du canvas vis.js* (DSH-BOUNDARY-1, livré ici car requis par
  « zéro CDN » et par la frontière S-216).
* **Activity stream** : les 60 sessions les plus récentes sont affichées,
  le badge indique `60 / 461 sessions` (le pivot JSON conserve **toutes** les
  sessions).
* **EPIC matrix** : plus aucun groupe `UNASSIGNED` (10 EPICs orphelins avant
  normalisation du propriétaire, 0 après).
* États vides conservés (aucun EPIC, aucune session, aucun jalon, aucun DAG).

=== 4. Zéro CDN

* Bootstrap **5.3.3** vendoré (`static/vendor/bootstrap.min.css`, 232 803 o,
  licence MIT conservée dans l'en-tête) ; copié vers `vendor/` (site plat) et
  `jbake/assets/css/` (site JBake).
* Suppression des scripts `cdn.jsdelivr.net` (Bootstrap JS, inutile) et
  `unpkg.com` (vis.js), du canvas et du JSON embarqué.
* Preuve : aucune référence `href="http…"` / `src="http…"` dans `index.html`.

=== 5. Configuration du consommateur racine
