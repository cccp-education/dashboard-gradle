== 2. DSH-BOUNDARY-2 — avancement réel (✅)

=== 2.1 Modèle

* `DashboardData.schemaVersion = "1.0"` (contrat public consommé par
  Brooklin Flow / Edster).
* `DashboardData.progress: ProgressSummary` :

[source]
----
ProgressSummary(donePoints, totalPoints, percent, doneEpics, totalEpics,
                byBorough: [BoroughProgress(borough, project, donePoints,
                totalPoints, percent, doneEpics, totalEpics)])
----

* `dashboard.progress.ProgressCalculator` (objet pur) : agrégation par points,
  `% = round(done*100/total)` borné 0..100, total nul → 0 %, boroughs sans
  EPIC conservés à zéro, EPICs orphelins comptés globalement.

=== 2.2 Sources

* **Par borough** : roadmap EPICs des `INDEX.adoc` (vue agrégée du backlog du
  borough) — source stable et déjà parsée.
* **Global transverse** : `BACKLOG.adoc` racine (`/home/cheroliv/workspace/`),
  table `EPIC | Sujet | Pts | Statut` → EPICs `GBL-*` rattachés au borough
  synthétique **« Transverse »** (`project = workspace-backlog`, DAG `GBL`).
* Nouvelle propriété d'extension `workspaceBacklog` (défaut vide) ;
  racine = `../../../BACKLOG.adoc` (`-Pdashboard.workspaceBacklog`).

=== 2.3 Rendu

* Carte **« Avancement global (points) »** : barre + `%` + `done/total pts` +
  `done/total EPICs`.
* Badge d'avancement dans chaque groupe borough de l'EPIC matrix
  (`X % (done/total pts)`, `—` si aucun point déclaré).
* Colonne **Avancement** dans la table des couches DAG.
* Le pivot JSON expose le détail complet (`progress.byBorough`).

=== 2.4 Bugs réels trouvés et corrigés (TDD/dogfood)

. **Colonne « Pts » capturée par `Description`** : `header.contains("pt")`
   matchait `description` (contient « pt ») → les points devenaient des dates
   → **~2 000 000 000 pts**. Correctif : header de points **exact**
   (`pts`/`points`) + `parsePoints` borné `0..1000`.
. **Statut accentué** : `contains("TERMINE")` ne matchait pas `TERMINÉ` →
   GBL-007/GBL-012 (46 pts terminés) comptaient comme planifiés. Correctif :
   `contains("TERMIN")` (+ `BLOQU`).
