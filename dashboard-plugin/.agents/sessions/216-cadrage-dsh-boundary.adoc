== Décisions architecturales (12)

1. Trois surfaces, trois rôles, zéro chevauchement : ALGER = pilotage
   (chiffres), Brooklin Flow = navigation (structure), Edster = interactif
   privé.
2. Source de données exclusive : ALGER lit les `.adoc` et produit
   `dashboard-data.json` (métriques seulement) ; graphify produit
   `graph.json` (structure seulement).
3. ALGER s'interdit tout canvas/graphe interactif et toute action serveur.
4. Brooklin Flow s'interdit tout calcul de métrique et tout parsing `.adoc`.
5. Retrait vis.js d'ALGER → table ordonnée N0→N4.
6. `dashboard-data.json` = contrat public versionné (`schemaVersion`).
7. L'interactif (lancer une tâche Gradle stricto local) vit dans Edster
   privé (REST + Gradle Tooling API, whitelist, bind local).
8. Zéro dépendance Gradle cross-borough — le couplage est le fichier JSON.
9. Edster = cadrage séparé (privé), hors gouvernance `foundry/public`.
10. English only (règle transverse).
11. Baby-step DDD/TDD/BDD strict RED → GREEN → REFACTOR.
